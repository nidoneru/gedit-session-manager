# Session Saver の動作仕様

> この文書では、Session Saver の動作を日本語で説明します。
> 仕様上の正本は `SESSION_BEHAVIOR.md` です。

## Previous Session とは

`Previous Session` は、gedit を終了する前に開いていたファイルを、次回起動時に復元するための特別なセッションです。

通常の名前付きセッションとは異なり、ユーザーが手動で作成するものではありません。Session Saver が自動的に内容を更新し、gedit のウィンドウでプラグインが有効になると自動的に復元します。

`Previous Session` という名前は予約されているため、同じ名前のセッションを作成したり、既存のセッションをこの名前に変更したりすることはできません。また、`Previous Session` 自体をユーザーが削除したり、名前を変更したりすることもできません。

## Previous Session が更新されるタイミング

`Previous Session` は、ウィンドウで開いている保存済み文書の構成が変わったときに更新されます。

現在は、次の操作をきっかけに保存が予約されます。

- タブを追加したとき
- タブを閉じたとき
- 文書に保存先が設定されたとき
- 文書の保存先が変わったとき

保存はその場ですぐに行うのではなく、タブや文書に対する処理が終わってから実行されるよう、アイドルコールバックを使っています。

すでに保存が予約されている場合は、同じ処理を重ねて予約しません。

## セッションに保存されるもの

セッションに保存されるのは、保存済み文書の場所です。

まだ一度も保存していない無題の文書は、保存先が決まるまでセッションには含まれません。

ファイルの並び順も記録され、復元時のタブの順序として使われます。

一方、次のような表示状態は保存しません。

- カーソル位置
- 選択範囲
- スクロール位置
- その他の表示状態

Session Saver が記録するのは、基本的に「どのファイルを、どの順番で開いていたか」です。

## 起動時の自動復元

ウィンドウでプラグインが有効になると、`Previous Session` の復元が予約されます。

復元も、プラグインの有効化処理の途中ですぐに行うのではなく、アイドルコールバックを使って実行します。

自動復元に失敗した場合は警告として記録しますが、この処理のためにモーダルなエラーダイアログは表示しません。

## 名前付きセッション

現在開いている保存済み文書を、任意の名前を付けてセッションとして保存できます。

保存済み文書が1つも開かれていない場合、空のセッションは作成せず、そのことをメッセージで知らせます。

`Previous Session` は予約名なので、名前付きセッションには使用できません。

セッション名に含まれる ASCII の英字は、大文字と小文字を区別せずに比較します。

たとえば、

- `Work`
- `work`
- `WORK`

は、すべて同じセッション名として扱います。そのため、`Work` が存在するときに `work` という別のセッションを新しく作ることはできません。

ただし、同じセッション自身の表記を変更することはできます。たとえば、既存の `WorK` を `Work` に変更する操作は許可されます。

## セッションを切り替えるとき

名前付きセッションを復元すると、現在開いている文書を閉じ、選択したセッションに記録されている文書へ切り替えます。

この切り替え処理は非同期で実行されます。

途中で処理がキャンセルされた場合や、何らかの理由で切り替えに失敗した場合は、セッションを復元できなかったことを警告します。原因によっては、保存や復元を担当する処理から詳しいエラー内容が表示されることもあります。

## 保存済みセッションの管理

「保存済みのセッション」ダイアログでは、名前付きセッションに対して次の操作ができます。

- 復元
- 名前の変更
- 削除

削除するときは、実際に削除する前に確認ダイアログを表示します。

また、一覧では次の操作も使えます。

- `Enter`：選択しているセッションを復元
- ダブルクリック：選択しているセッションを復元
- `F2`：選択しているセッションの名前を変更

セッションを新しく保存したときや、名前を変更・削除したときは、gedit のアプリケーションメニューも更新します。これにより、メニューに表示されるセッションの一覧と実際の保存内容が一致するようにしています。

## 保存に失敗した場合

セッション情報は `saved-sessions.xml` に保存します。

このファイルへの書き込みに失敗した場合は、エラーとして扱います。

`Previous Session` の自動更新に失敗した場合は警告として記録します。

ユーザーが操作する名前付きセッションについては、保存・名前変更・削除に失敗するとエラーダイアログを表示します。

なお、セッションを切り替えるときに未保存の変更がある文書をどう扱うかは、セッション情報そのものではなく、非同期の文書切り替え処理が担当します。
